# Термины, OSI, стек TCP/IP

Сеть - множество устройств, соединенных физически и логически.
- Физически = есть среда передачи данных (кабель, воздух).
- Логически = устройства понимают друг друга (протоколы).

Состав сетей:
- оконечные узлы = принимают и передают данные
- промежуточные узлы = соединяют оконечные узлы
- среда передачи = среда, где передаются данные (кабели, воздух)

Терминал = функционал заключается в двух вещах: 
1. простая работа со считыванием данных
2. передача по сети на сервер

Тонкий клиент (бездисковая рабочая станция) = оболочка для оцифровки данных с сервера:
1. есть плата, процессор, RAM, сетевой кабель
2. тонкий клиент выступает промежуточным звеном между клиентом и сервером: клиент нажал -> тонкий передал запрос -> сервер сказал что отрисовать -> тонкий отрисовал

Хаб (Концентратор) - промежуточный узел, получает данные -> отправляет на ВСЕ порты
Свитч (Коммутатор) - промежуточный узел, получает данные -> смотрит на MAC адрес -> смотрим в таблицу (MAC->порт) -> отправляет в нужны порт
Роутер (Маршрутизатор) - промежуточный узел, получает данные -> смотрит на ip -> определяет наилучший путь -> отправляет
Модем (Modulator-Demodulator) - промежуточный узел, превращает цифровой сигнал -> сигнал среды
Точка доступа (AP = Access Point) - промежуточный узел,

Порт:
- нужен для установления соединения.
аналогия: ip - адрес дома, порт - номер квартиры.

MAC-адрес (Media Access Control):
- уникален, физически вшит в железо
- состоит из 12 шестнадцатеричных цифр (48бит)
аналогия: ip - адрес дома, mac - паспорт жильца

MAC Address Table:
- находится на свитче
- таблица ключ значение (MAC - порт коммутатора)
- при первом запуске таблица пуста. заполнение происходит так:
    1. данные пришли от ПК с MAC1 на порт1 => заполняем
    2. если данных об получателе нет => рассылаем по все портам.
    3. получаем ответ заполняем таблицу.

ARP (Address Resolution Protocol):
- задача: по IP найти MAC в LAN
1. смотрим в ARP-кэш (находится на устройстве-отправителе).
2. если нет MAC - Broadcasting: "У кого IP ... скажите MAC".
3. обновляем ARP-кэш.
4. Теперь можно передавать данные на L2.

FTP поверх TCP, порт 21
TFTP (Trivial) поверх UDP, порт 69

VoIP и VoLTE:
- VoIP: раньше голос передовался по специальны телефонным сетя, эта технология передает голос через сети
- VoLTE: позволяет передавать пакеты по 4G вместо 3G/2G как раньше

Топология сетей:
- физическая = как устроена сеть, как соединены узлы
- логическая = как передаются данные

Виды Топологий:
1. Bus Topology
2. Ring Topology - передача данных в одном направлении по кругу
3. Star Topology - центр - свитч
4. Full-Mesh Topology - полный граф
5. Partial-Mesh Topology - неполный граф
6. Hybrid Topology

OSI:
1. Физический (Physical) - про то, как передаются данные, какой тип среды, характеристики среды.
2. Канальный (Data Link) - про то, как передаются данные / обнаружение ошибок в ЛОКАЛЬНОЙ сети. (MAC адрес, коммутатор)
3. Сетевой (Network) - про выбор оптимального пути в ГЛОБАЛЬНОЙ сети. (IP адрес)
4. Транспортный (Transport) - про то, как организовать транспортировку / обнаружение ошибок = все ли пакеты дошли. (порты, TCP, UDP)
5. Сеансовый (Session) - про то, как работать с несколькими сеансами: установка, разрыв соединения. к одному сервер же может несколько пользователей подключиться.
6. Представления (Presentation) - подготовка данных для интерпретации на Прикладном уровне.
7. Прикладной (Application) - про то, как общаются приложения. (HTTP, FTP)
Путь непрерывен!

* Деинкапсуляция

7. Прикладной (Application) - приложение понимает, что нужно сделать (сервер понял, что нужно отдать index.html)
